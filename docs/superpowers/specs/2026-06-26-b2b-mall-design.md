# B2B 智能批发商城 — 系统设计文档

> 版本: v2.0 | 日期: 2026-06-26 | 状态: 待入驻计划

---

## 一、项目概述

面向下游零售商的 **儿童产品 B2B 批发商城**，以 AI 对话式下单为核心差异化能力，前端使用 uni-app 开发微信小程序。

### 核心定位

**品类聚焦** — 专注儿童游泳设备、儿童护肤产品、儿童健康产品三大品类，垂直精品批发。最终消费者是孩子，采购决策者是零售商，商城需要同时打动两者：让零售商看到品质和利润空间，让产品呈现传递对孩子温柔的关爱。

### 核心诉求

1. **B2B 批发供货** — 下游零售商可通过传统浏览或 AI 对话完成选品、议价、下单、支付全流程
2. **店面设计服务** — 作为虚拟商品上架（"实体店店面设计"），配合精美历史案例图库展示设计实力，下单后由设计师线下对接交付
3. **AI 智能客服** — 本地知识库 + 对话下单 + 用户画像记忆 + 个性化推荐，AI 取名"小暖"
4. **大模型对接** — DeepSeek V4 Pro、千问等国内主流模型，支持场景化路由切换
5. **微信小程序** — uni-app (Vue3 + TypeScript) 跨端开发，亲子温馨视觉风格

### 业务规模预估

- **初期阶段**: 数百 SKU，3 大品类（游泳设备 / 护肤产品 / 健康产品），垂直精品批发
- **用户角色**: 平台管理员、零售商（买家）、运营人员、设计师

## 二、技术选型

| 层面 | 技术 | 理由 |
|------|------|------|
| 后端框架 | Python / FastAPI | AI/NLP 生态最成熟，异步高性能 |
| 数据库 | PostgreSQL + pgvector | JSON 灵活字段 + 向量检索（知识库 RAG） |
| 缓存 | Redis | 会话、热数据、用户画像缓存、AI 对话状态 |
| AI 框架 | LangChain + 自研路由层 | RAG 编排 + 模型切换 |
| 大模型 | DeepSeek V4 Pro、千问 qwen-max | OpenAI 兼容 API，统一适配 |
| 消息队列 | Redis Pub/Sub（初期），后续可升 RabbitMQ | 业务服务 ↔ AI 服务异步通信 |
| 文件存储 | 阿里云 OSS / 腾讯云 COS | 商品图、案例图、上传文档 |
| 前端 | uni-app (Vue3 + TS) + uView Plus | 微信小程序为主，架构支持扩展到其他平台 |
| 部署 | Docker + Nginx | 容器化，便于 AI 服务独立扩缩 |

## 三、架构设计

### 3.1 总体架构：模块化单体 + AI 独立服务

```
┌─────────────────────────────────────────────────────┐
│                 Nginx (HTTPS)                       │
└──────┬──────────────────────────────────────────────┘
       │
┌──────▼──────────────────────────────────────────────┐
│              API Gateway (FastAPI 路由层)            │
│    /api/v1/auth     /api/v1/products                │
│    /api/v1/orders   /api/v1/payments                │
│    /api/v1/ai/*       → 转发AI服务                   │
└──────┬──────────────────────────┬───────────────────┘
       │                          │
┌──────▼──────────┐    ┌──────────▼──────────────────┐
│ 核心业务服务     │    │     AI 服务 (独立部署)        │
│ (FastAPI 模块)   │    │  ┌───────────────────────┐  │
│                 │    │  │ AI对话下单引擎          │  │
│ • 商品管理       │◄──►│  │ • 意图识别              │  │
│ • 定价引擎       │ 内 │  │ • 对话状态机            │  │
│ • 订单/履约      │ 部 │  │ • 订单构建器            │  │
│ • 用户/角色      │ API│  ├───────────────────────┤  │
│ • 支付/账期      │    │  │ 知识库引擎              │  │
│ • 案例图库       │    │  │ • 商品知识同步          │  │
│                 │    │  │ • RAG检索增强            │  │
│                 │    │  │ • 文档解析摄取          │  │
│                 │    │  ├───────────────────────┤  │
│                 │    │  │ 用户画像 & 推荐           │  │
│                 │    │  │ • 购买习惯分析            │  │
│                 │    │  │ • 个性化推荐              │  │
│                 │    │  ├───────────────────────┤  │
│                 │    │  │ 模型路由层               │  │
│                 │    │  │ DeepSeek V4 ←→ 千问      │  │
│                 │    │  │ 统一适配 + 降级切换       │  │
│                 │    │  └───────────────────────┘  │
└──────┬──────────┘    └──────────┬──────────────────┘
       │                          │
┌──────▼──────────────────────────▼──────────────────┐
│          PostgreSQL + Redis + 文件存储              │
└────────────────────────────────────────────────────┘
```

**通信方式:**
- 小程序 ↔ 核心业务: REST API (HTTPS)
- 小程序 ↔ AI 服务: WebSocket（对话流）+ REST（推荐/查询）
- 核心业务 ↔ AI 服务: 内部 REST + Redis Pub/Sub（异步事件：订单完成通知AI更新画像等）

**设计原则:**
- 业务服务模块化但不过早拆微服务 — 数百 SKU 阶段单体更高效
- AI 服务从第一天独立部署 — 推理耗时不影响交易链路
- 两者通过内部 API + 消息队列通信，边界清晰

## 四、视觉设计系统

### 4.1 品牌调性

**亲子温馨风** — 暖色调、圆润设计语言、柔软质感，传递"给孩子最好的"情感价值。

| 维度 | 策略 |
|------|------|
| 主色调 | 温暖珊瑚粉 `#FF7B7B` + 奶油米白 `#FFF8F0` 为基调 |
| 辅助色 | 柔和天空蓝 `#7EC8E3`、薄荷绿 `#A8D8B9`（与游泳/健康品类呼应） |
| 强调色 | 蜂蜜黄 `#FFD93D`（促销标签、CTA按钮） |
| 圆角 | 全局圆角 12-16px，卡片圆角 20px，按钮胶囊形 |
| 字体 | 标题使用圆体/柔体风格，正文清晰易读 |
| 图标 | 手绘插画风格，儿童元素融入（游泳圈、小鸭子、小树苗等） |
| 阴影 | 轻柔弥散阴影，避免硬边 — `box-shadow: 0 4px 20px rgba(0,0,0,0.06)` |

### 4.2 情感设计元素

```
页面氛围:
├── 柔和渐变背景（奶油色 → 浅粉）
├── 装饰性手绘元素轻点缀（非侵入式）
├── 产品图圆角卡片 + 柔和倒影
├── 儿童使用场景的温馨插画（非真实儿童照片，保护隐私）
└── 微动效：卡片hover轻轻上浮、爱心飘动等

安全/品质传递:
├── 产品认证标识醒目展示（如安全认证、材质认证徽章）
├── "适合X岁+" 友好标签
└── 材质/成分透明化展示
```

### 4.3 图片策略

- **商品图**: 白底/浅色底产品图 + 儿童使用场景图（温馨光线、生活化场景）
- **店面设计案例图**: 全屏大图展示，支持手势缩放，瀑布流排列如 Pinterest 风格（案例图精细度高，展示设计实力）
- **Banner**: 高精度摄影/渲染图，配合柔和渐变叠加文字
- **图片格式**: WebP 优先，渐进式加载，懒加载

### 4.4 品牌记忆点

- **超级符号**: 一个温暖的小太阳/笑脸图标，贯穿首页、加载页、AI头像
- **AI助手人格**: 取名"小暖"，头像为暖色卡通形象，对话语气温柔贴心但专业
- **Slogan**: "给孩子温柔的呵护"

## 六、核心数据模型

### 6.1 用户体系

```
users
├── role: admin | retailer | operator | designer
├── level: normal | silver | gold | platinum   -- 零售商等级
├── credit_limit: Decimal     -- 账期总额度
├── credit_balance: Decimal   -- 已用额度
├── status: pending_review | active | frozen
└── auth: phone + wx_openid

retailer_profiles
├── user_id → users
├── company_name, business_license, contact_person
├── purchase_history_summary: JSON   -- AI定期更新的购买画像摘要
└── preferred_categories: JSON       -- 偏好品类

designer_profiles
├── user_id → users
├── portfolio: JSON                  -- 作品集
├── specializations: text[]
└── active_orders_count: int
```

### 6.2 商品与定价

```
categories
├── parent_id → categories (树形)
├── name: 儿童游泳设备 | 儿童护肤产品 | 儿童健康产品
├── icon, sort_order
└── status: active | hidden

products
├── category_id → categories
├── name, images[], description, specs: JSON
├── age_range: str            -- "3-6岁" / "0-3岁" / "6岁+"
├── safety_certifications: JSON  -- [{"name":"3C认证","icon":"..."}]
├── is_virtual: bool          -- false=实物商品, true=店面设计服务
├── virtual_detail: JSON      -- 虚拟商品专属字段(设计服务:面积/风格/预算)
├── stock: int                -- 虚拟商品为null
├── ai_knowledge_id → ai_knowledge_entries
└── status: on_sale | off_sale | deleted

pricing_rules (每个商品的定价矩阵，JSON字段)
示例:
{
  "gold":    [{"qty": 10, "price": 80}, {"qty": 50, "price": 72}, {"qty": 100, "price": 65}],
  "silver":  [{"qty": 10, "price": 88}, {"qty": 50, "price": 79}, {"qty": 100, "price": 72}],
  "normal":  [{"qty": 10, "price": 95}, {"qty": 50, "price": 85}, {"qty": 100, "price": 78}]
}
```

### 6.3 设计案例图库

```
design_cases (独立于商品表，用于展示设计实力)
├── title, description
├── images[]                   -- 高清案例图(支持多张)
├── category_tags[]            -- "婴童游泳馆" / "母婴生活馆" / "儿童乐园"
├── style_tags[]               -- "ins风" / "自然原木" / "卡通童趣"
├── store_area_range           -- "50-100㎡" / "100-200㎡" / "200㎡+"
├── sort_order, is_featured    -- 是否精选(决定首页展示)
└── status: published | draft
```

### 6.4 订单

```
orders
├── order_no: str (唯一)
├── type: physical_goods | store_design
├── retailer_id → users
├── items: JSON
│   [{"product_id": X, "name": "儿童游泳圈", "qty": 100, "unit_price": 35, "subtotal": 3500}]
├── total_amount: Decimal
├── pricing_snapshot: JSON      -- 下单时锁定的价格快照(防止争议)
├── payment
│   ├── method: wechat_pay | bank_transfer | credit
│   ├── status: pending | paid | confirmed | overdue
│   └── credit_used: Decimal    -- 使用账期的金额
├── status: pending_payment → paid → shipped → confirmed → completed
├── store_design_detail: JSON | null
│   ├── store_area, style_preference, budget_range
│   ├── assigned_designer_id → users
│   ├── attachments[]           -- 店面照片/尺寸图
│   └── delivery_progress: brief → draft → revision → finalized
├── ai_conversation_id          -- AI对话下单的对话记录引用
└── timeline: JSON              -- 状态变更时间线
```

## 七、定价引擎

### 7.1 价格计算流程

```
用户查看商品 → 读取用户等级(level) + 输入数量(qty)
  → 匹配 pricing_rules[level] 找到对应阶梯
  → 返回单价 + 总价
  → 如低于起批数量 → 提示最低起批量
```

### 7.2 设计原则

- 定价规则在商品上架时配置，下单时做**快照**固化
- 管理员修改定价规则不影响已生成订单
- 支持批量导入/导出定价表

## 八、支付与结算

| 支付方式 | 适用场景 | 说明 |
|----------|----------|------|
| 微信支付 | 小额订单 | 小程序原生支持，受单笔限额 |
| 银行转账 | 大额订单 | 上传转账凭证 → 运营后台确认 |
| 账期授信 | 优质零售商 | gold+等级可用，按月结算，额度内免密下单 |

**账期管理:**
- 管理员为零售商设定 `credit_limit`
- 下单时 `credit_balance + 本次金额 ≤ credit_limit` 方可使用
- 每月生成账单，零售商还款后恢复额度
- 逾期自动冻结账期权限

## 九、AI 对话下单引擎

### 9.1 核心流程

```
用户输入 → [意图识别] → [用户画像读取] → [知识库RAG检索]
  → [LLM生成回复+操作指令] → [返回富消息给前端]
  → 循环直到订单确认
```

### 9.2 意图类型（儿童产品场景示例）

| 意图 | 说明 | 示例 |
|------|------|------|
| `recommend` | 推荐商品 | "3岁宝宝用哪种游泳圈合适" |
| `search` | 搜索查询 | "有没有防晒的儿童护肤品" |
| `order` | 下单操作 | "第一款拿100件" |
| `negotiate` | 议价/数量协商 | "200件能便宜点吗" |
| `query` | 信息查询 | "这款有安全认证吗，适合多大孩子" |
| `reorder` | 补货 | "夏天快到了，上次的游泳装备再来一批" |

### 9.3 对话状态机

```
IDLE → RECOMMENDING (推荐中) → BUILDING_ORDER (构建订单) → CONFIRMING (确认中) → COMPLETED
  │         │                        │                      │
  └─────────┴────────────────────────┴──────────────────────┘
                    任意状态可回退到IDLE (取消/重置)
```

### 9.4 订单构建器

从对话上下文中提取结构化订单信息：
- 商品 ID、数量
- 匹配价格（用户等级 × 数量阶梯）
- 支付方式偏好
- 生成 `orders` 记录并返回订单号

订单构建器在创建订单前必须通过校验：商品存在、库存充足、金额正确。校验失败时回传 AI 生成错误提示。

### 9.5 富消息类型

| 消息类型 | 内容 | 触发时机 |
|----------|------|----------|
| `text` | 纯文本 | 普通对话 |
| `product_card` | 商品缩略图+名称+批发价+适龄标签+库存 | 商品推荐 |
| `order_confirm` | 商品清单+数量+价格+支付方式选择 | 订单待确认 |
| `order_result` | 订单号+状态+预计送达 | 下单成功 |
| `quick_replies` | 快捷回复按钮 | 引导用户选择 |

## 十、知识库引擎

### 10.1 知识来源

| 来源 | 方式 | 更新频率 |
|------|------|----------|
| 商品基础信息 | 自动同步 name/description/specs/age_range → 向量嵌入 | 商品变更时实时 |
| 商品卖点话术 | 运营手动录入或文档上传 | 按需 |
| FAQ 问答对 | 手动录入 + 上传文档自动解析 | 按需 |
| 安全认证知识 | 儿童产品相关的认证标准、材质知识录入 | 按需 |
| 成功对话沉淀 | AI 自动标记有效推荐链 → 提取加入知识库 | 运营审核后 |

### 10.2 技术实现

```
知识摄取流程:
  手动文本/文档上传 → 分段(Chunking) → Embedding(向量化)
    → pgvector 存储 → 更新索引

检索流程(RAG):
  用户问题 → Embedding → pgvector 相似度搜索 → Top-K结果
    → 注入LLM上下文 → 生成回复
```

### 10.3 文档解析支持

- PDF: PyPDF2 / pdfplumber
- Word: python-docx
- Excel: openpyxl（批量商品信息导入同时生成知识条目）
- 纯文本/富文本: 直接分段处理

### 10.4 学习机制

- **正向强化**: 对话最终成功下单 → 该轮对话链标记为有效 → 提取关键推荐话术 → 运营审核后入库
- **负向惩罚**: 用户明确纠正("不对，我要的是XX") → 降低对应知识条目权重
- **趋势学习**: 统计高频问题 → 自动生成 FAQ 草稿 → 运营确认发布
- **季节性知识**: 自动识别儿童产品季节性（游泳设备夏季热销、护肤品秋冬需求大）→ 知识库权重随季节调整

## 十一、用户画像与推荐引擎

### 11.1 画像维度

| 维度 | 数据来源 | 说明 |
|------|----------|------|
| 品类偏好 | 历史订单品类分布 | 偏游泳还是护肤还是健康，加权 |
| 适龄段偏好 | 历史商品 age_range | 零售商服务的核心儿童年龄段 |
| 价格带偏好 | 历史订单单价区间 | 偏好价位段 |
| 品牌偏好 | 历史订单品牌分布 | 复购品牌识别 |
| 采购周期 | 订单时间间隔分析 | 预测补货时间 |
| 采购量偏好 | 历史每单数量 | 推荐匹配的阶梯价档位 |
| 季节性偏好 | 品类×月份交叉分析 | 游泳设备夏季、护肤入秋等 |
| 对话偏好 | AI对话中的交互风格 | 简洁型/详细型 |

### 11.2 推荐场景

| 场景 | 触发方式 | 说明 |
|------|----------|------|
| 首页推荐 | 被动展示 | 基于画像的个性化商品推荐 |
| AI对话推荐 | 主动触发 | 用户发起对话时结合画像做推荐 |
| 补货提醒 | 推送通知 | 根据采购周期+季节预测，主动提醒补货 |
| 新品匹配 | 推送通知 | 新商品匹配零售商偏好时通知 |
| 季节换品 | 推送通知 | 换季前提醒采购应季品类 |

### 11.3 画像更新

- 订单完成后异步更新（Redis Pub/Sub 触发）
- AI 对话结束后批量更新交互偏好
- 每周离线全量重算画像摘要（存入 `retailer_profiles.purchase_history_summary`）

### 13.4 技术栈

## 十四、分阶段开发路线

### Phase 1：MVP 核心交易链路 + 品牌视觉（预计 4-6 周）

## 十五、非功能需求

| 维度 | 要求 |
|------|------|

## 十六、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| AI 对话下单转化率低 | 核心差异化失效 | Phase 2 上线后快速 A/B 测试，对比传统下单转化率 |
| 大模型 API 不稳定 | 对话功能不可用 | 双模型互备降级 + 固定话术兜底 |
| 微信小程序审核 | 上线延迟 | 提前准备审核材料，AI功能做好降级方案 |
| 知识库冷启动 | 初期推荐不准 | Phase 1 先积累订单数据，Phase 2 知识库人工录入先行 |
| 案例图版权 | 法律风险 | 仅展示已交付项目的授权图片，合同约定使用权 |
| 儿童产品合规 | 宣传风险 | 适龄标签/认证展示务必真实准确，AI话术需审核 |
| 账期坏账 | 资金风险 | 严格准入审核 + 额度阶梯释放 + 逾期自动冻结 |
